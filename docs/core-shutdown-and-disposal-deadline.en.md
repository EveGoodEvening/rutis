# Root Shutdown and Disposal Wait Deadlines

`dispose()` retains its existing behavior: it waits indefinitely and the root can be restarted. The new `FiberView::dispose_with_timeout(limit)` registers the same disposal task synchronously and sets a deadline only for the caller's wait. A timeout reports the plugin ID, generation, current state, and elapsed wait. `Loading` means `apply` has not exited; `Unloading` means cleanup or the dependent-consumer cascade is still in progress. If the request is queued behind an earlier long-running task, it may observe `Active` or `Pending`. After a timeout, the driver continues working. A later `dispose()` joins the original task, and cleanup errors reuse the same `Arc<CordisError>`. A timeout does not claim the plugin stopped or change the service graph.

Synchronous `dispose()` registration also closes admission to new generations. An initial dependency refresh or restart already in the queue cannot run `apply` for a generation that has not been admitted. If generation admission wins first, disposal cancels that generation's installed token so an `apply` waiting for `ctx.cancelled()` can exit cooperatively. Terminal registration and generation admission share the transition lock.

`Ctx::shutdown()` is the final shutdown entry point for a root. It first blocks new services, effects, and plugin mounts, then waits for mounted subtrees admitted before closure to clean up and for the root driver to end. Repeated or concurrent calls share one completion result. If a child fiber was created but its mount was rejected because the root was closing, it never enters `apply` and shuts down independently. The root completion does not wait for this unmounted driver; a holder of its returned `FiberView` can call `shutdown()` to wait for it. `Ctx::shutdown_with_timeout(limit)` limits only this wait. After a timeout, root shutdown continues and a later `shutdown()` can join it. Root `dispose()` and `restart()` remain usable as a pair until `shutdown()` is called. After shutdown, `restart` and new registrations return `CordisError::Closed`. Because the existing `plugin()` API returns a `FiberView`, it returns a terminal view whose wait result is `Closed`. `Ctx::root_view()` now returns `Option<FiberView>` and returns `None` after the root driver ends and the last view is dropped.

Forced isolation after timeout is not implemented. An old generation's `apply` or cleanup may continue holding capabilities if it ignores cancellation, so a timed-out wait cannot safely mark it stopped or start another generation. Tokio timers also cannot fire on time while synchronous code occupies the same runtime thread without yielding. Process and process-tree management belongs to the caller's tooling layer.
